##  Запись изменений в БД с помощью `$merge`

### 1. Ключевые особенности

Стадия `$merge` позволяет записывать изменения, созданные на предыдущих стадиях,  
в указанную коллекцию (чаще всего в текущую).

⚠️ ВАЖНО: `$merge` изменяет коллекцию (записывает изменения в БД!).

```js
db.collection.aggregate(
  [
    {
      $addFields: {
        new_field: 1000   // добавление нового поля
      }
    },
    
    {  // закрепление результата в БД
      $merge: {
        into: "target_collection",
        // Куда записать результат (Здесь: результат aggregation записывается в коллекцию "target_collection")
        
        on: "field",
        // Необязательный параметр.
        // По какому полю (или списку полей) определить, какой документ в target_collection считается совпадающим.
        // Если не указан — используется _id
        
        let: { variableName: "$expression" },
        // Необязательный параметр.
        // Создаёт переменные, которые можно использовать  в whenMatched
        
        whenMatched: "merge",
        // Что делать при совпадении. (Здесь: "merge" — объединить входящий документ с существующим документом)
        
        whenNotMatched: "insert"
        // Что делать при отсутствии совпадения. (Здесь: "insert" — добавить входящий документ)
      }
    }
  ]
);
```

---

#### Варианты параметра `whenMatched`

Определяет, что делать, если документ с указанным `on`-полем уже существует в целевой коллекции.

| Значение         | Что делает                                                        |
| ---------------- | ----------------------------------------------------------------- |
| `"replace"`      | Полностью заменяет существующий документ результатом aggregation  |
| `"merge"`        | Объединяет поля существующего и входящего документа               |
| `"keepExisting"` | Оставляет существующий документ без изменений                     |
| `"fail"`         | Вызывает ошибку при совпадении                                    |
| `"pipeline"`     | Запускает указанный aggregation pipeline для обновления документа |


---

#### `whenNotMatched`

Определяет, что делать, если соответствующего документа в целевой коллекции нет.

| Значение    | Что делает               |
| ----------- | ------------------------ |
| `"insert"`  | Добавляет новый документ |
| `"discard"` | Игнорирует документ      |
| `"fail"`    | Вызывает ошибку          |


---

### 2. Часто используемые комбинации

**1. Обычный upsert:**

```javascript
{
  $merge: {
    into: "target_collection",
    whenMatched: "merge",
    whenNotMatched: "insert"
  }
}
```

**2. Полная замена совпавшего по `_id` документа:**

```javascript
{
  $merge: {
    into: "target",
    whenMatched: "replace",
    whenNotMatched: "insert"
  }
}
```

⚠️ Это особенно важно, если ранее было удаление полей (например, с помощью стадии`$unset`)

**3. Только обновлять существующие документы (полной заменой), новые не добавлять.:**

```javascript
{
  $merge: {
    into: "target",
    whenMatched: "replace",
    whenNotMatched: "discard"
  }
}
```

**4. Только добавлять новые, существующие не трогать:**

```javascript
{
  $merge: {
    into: "target",
    whenMatched: "keepExisting",
    whenNotMatched: "insert"
  }
}
```

### 3. Главное отличие`$merge` от `$out`

Прежде всего:
* `$merge` -> обновить / добавить данные в **существующую** коллекцию 
  * (**можно настроить** сохранение предыдущих данных)
* `$out` -> **полностью заменить** старую коллекцию на новую
  * (прежние данные будут удалены и перезаписаны **без вариантов**)

### 4. Главное сходство `$merge` и `$out`

Если создаётся новая коллекция, разницы между ними нет.
